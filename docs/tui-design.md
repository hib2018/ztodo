# TUI操作設計

この文書では、`ztodo`の画面構成と操作規則を定義する。
実装はキーボード操作を中心とし、既存のANSI Terminalバックエンドを使用する。

## 基本方針

- 現在の操作対象と利用可能なキーを常に画面へ表示する。
- `Esc`は現在のpopupや編集をキャンセルし、一つ前の状態へ戻る。
- 破壊的操作はキャンセルを既定とし、小文字の`y`が入力された場合だけ実行する。
- Taskの完了状態は元に戻せるため、変更時に確認を求めない。
- 項目を並べ替えた後も、移動した項目を選択し続ける。
- 項目を削除した後は次の項目を選択する。末尾を削除した場合は一つ前を選択する。
- 入力内容の検証が成功するまでファイルを変更しない。
- Task操作の成功時はpopupを表示せず、失敗時だけエラーpopupを表示する。
- 選択移動とタブ切り替えはデータを変更しないため、popupを表示しない。

## 画面構成

画面を左側の固定サイドバーと右側の詳細画面に分割する。
サイドバーには`タスク一覧`、`リポジトリ一覧`、`プロンプト編集`、`ヘルプ`を表示する。
選択した項目に対応する内容を右側へ表示し、各一覧の選択位置は画面を切り替えても保持する。

```text
┌────────────────────┬──────────────────────────────────────┐
│ ztodo v0.3.0       │ タスク一覧                           │
├────────────────────┼──────────────────────────────────────┤
│ > タスク一覧       │ > [ ]    3  画面を設計する           │
│   リポジトリ一覧   │   [x]    5  Task一覧を実装する       │
│   プロンプト編集   │   [ ]    6  Task操作を実装する       │
│   ヘルプ           │                                      │
│                    │                                      │
├────────────────────┼──────────────────────────────────────┤
│ Tab 詳細へ         │ j/k 選択  a 追加  Tab メニュー       │
└────────────────────┴──────────────────────────────────────┘
```

サイドバーの幅は22列とする。Terminal全体が最小幅48列の場合も右側へ操作可能な詳細領域を残す。
サイドバーと詳細画面は境界の罫線を共有し、それぞれの見出しと操作案内を持つ。

### Tasks画面

- メイン領域へ、保存されている順序で全Taskを表示する。
- 起動直後は、ztodo自身がTask一覧をalternate screen全体へフルスクリーンで描画する。
- Terminalの実際の行数・列数を取得し、起動画面のpanelは余白と影を付けず画面端まで表示する。
- 各行には完了状態、変更されないTask ID、タイトルを表示し、完了状態のTaskには行の右端まで取り消し線を付ける。
- 選択中の行をハイライトする。
- 項目数が多い場合は、選択行が表示範囲内に残るようスクロールする。
- タイトルがpanelの右端までに収まらない場合は、UTF-8文字のTerminal上の表示幅を考慮して折り返す。
- 折り返した2行目以降は、1行目のタイトル開始位置より1列右へずらして表示する。
- 折り返しによる可変行数を含め、選択中のTaskがpanel内に残るようスクロール位置を計算する。
- Taskがない場合は`Taskはありません。aで追加できます。`と表示する。

### Proposal画面

```text
 ztodo    Tasks  [Proposal]
────────────────────────────────────────────────────────────
 GitHub owner/repo #24: Issueのタイトル
 概要: Proposalの概要

 > 1. 最初のTask候補
   2. 次のTask候補

────────────────────────────────────────────────────────────
 k 前へ  j 次へ  a 追加  e 編集  d 削除  K/J 並び替え
 A 承認           q Tasksへ戻る          ? ヘルプ
```

- ヘッダーへProposalの生成元と概要を表示する。
- メイン領域へProposal内の順序でTask候補を表示する。
- Proposalがない場合は、`ztodo issue`と`ztodo import`による作成方法を表示する。
- 最初のTUI実装ではProposalのメタデータを読み取り専用とする。
- Task候補の編集にはTask編集と共通の入力popupを使用する。

### プロンプト編集画面

- 保存済みのAI向け追加指示を右側へ表示する。
- 改行を保持し、詳細領域の幅で折り返す。
- `e`でTUIを一時停止し、`VISUAL`または`EDITOR`に設定された外部エディタを起動する。
- エディタ終了後に追加指示を再読み込みし、プロンプト編集画面へ戻る。
- 外部エディタまたは検証に失敗した場合は既存の追加指示を保持し、エラーpopupを表示する。

### ヘルプ画面

- popupではなく右側の詳細画面へ共通操作と画面別操作を表示する。
- popup操作中のヘルプは従来どおり最前面のpopupを優先する。

## フォーカスと移動

フォーカスの優先順位を次のように定める。

1. 入力または確認popup
2. サイドバーまたは詳細画面のうち現在フォーカスされている領域
3. 詳細画面内で選択されている行

popupが開いていない場合だけ、`Tab`でサイドバーと詳細画面のフォーカスを切り替える。
サイドバーでは`j`/`k`または矢印キーで項目を移動すると右側の詳細も切り替わり、`Enter`で詳細へフォーカスする。
詳細画面の`h`でサイドバーへ戻る。
Tasks画面の`p`でProposal画面を開き、Proposal画面の`q`でTasks画面へ戻る。
各画面は、それぞれの選択行とスクロール位置を保持する。
タブの切り替えによってデータを変更してはならない。

一覧内では次のキーを使用する。

- `k`または`↑`：一つ前の行を選択する
- `j`または`↓`：一つ次の行を選択する
- トラックパッド：macOSのナチュラルスクロールに合わせ、上方向で次、下方向で前の行を表示する
- `Home`または`g`：先頭行を選択する
- `End`または`G`：末尾行を選択する
- `PageUp`または`PageDown`：表示一画面分移動する
- `K`または`J`：選択中の項目を一つ上または下へ移動する

一覧の端から反対側へ循環移動はせず、先頭または末尾で停止する。

## キーバインド

### 共通操作

| キー | 操作 |
| --- | --- |
| `Tab` | サイドバーと詳細画面のフォーカスを切り替える |
| `h` | 詳細画面からサイドバーへフォーカスを移す |
| `?` | 現在の画面に対応したヘルプpopupを開く |
| `q` | サイドバーでは終了する。子画面では一つ前へ戻り、プロンプト編集・ヘルプではサイドバーへ戻る |
| `Esc` | 最前面のpopupを閉じる、または編集をキャンセルする |
| `Ctrl-C` | 現在のpopupをキャンセルする。メイン画面では終了する |

### Tasks画面

| キー | 操作 |
| --- | --- |
| `a` | 空のタイトル入力を開き、Taskを追加する |
| `e` | 選択中のTaskを、現在のタイトルが入力済みの状態で編集する |
| `Space` | 選択中のTaskの未完了と完了を切り替える |
| `d` | 確認後、選択中のTaskを削除する |
| `C` | 確認後、全Taskを削除して次のIDを1へ戻す |
| `K` / `J` | 選択中のTaskを一つ上または下へ移動する |
| `r` | Repositories画面を開く |
| `g` | 登録RepositoryのOpen Issue一覧を取得してIssues画面を開く |
| `p` | Proposal画面を開く |

### Proposal画面

| キー | 操作 |
| --- | --- |
| `a` | Task候補を追加する |
| `e` | 選択中のTask候補を、現在のタイトルが入力済みの状態で編集する |
| `d` | 確認後、選択中のTask候補を削除する |
| `K` / `J` | 選択中のTask候補を一つ上または下へ移動する |
| `A` | Proposalを検証し、全体の承認確認を開く |
| `i` | ClipboardからProposal JSONを検証して取り込む |

項目の選択が必要なキーは、一覧が空の場合には何もしない。
画面下部には、その時点で実行可能な操作だけを表示する。

### Repositories画面

Tasks画面の`r`で開く。登録済みRepositoryを一覧表示し、次の操作を提供する。
展開したRepositoryの直下へIssueをインデントして表示し、複数Repositoryを同時に展開できる。取得済みIssueはRepository名ごとに保持し、`r`が押されるまで再利用する。取得失敗時は既存の展開内容を保持する。

| キー | 操作 |
| --- | --- |
| `j` / `k`、`↓` / `↑` | Repositoryを選択する |
| `Space` | 選択中Repositoryを展開・折りたたみし、直下へOpen Issueを表示する |
| `Enter` | 選択中IssueのAI向けプロンプトをClipboardへコピーする |
| `r` | 選択中RepositoryのOpen Issueを再取得する |
| `a` | `owner/repository`形式でRepositoryを追加する |
| `d` | 確認後、選択中のRepositoryを削除する |
| `q` | Tasks画面へ戻る |

### プロンプト編集画面

| キー | 操作 |
| --- | --- |
| `e` | TUIを一時停止し、外部エディタでAIへの追加指示を編集する |
| `q` | サイドバーへ戻る |

### Issues画面

Tasks画面の`g`で、全登録RepositoryのOpen Issueを独立した一覧として表示する。Repositories画面ではIssueを別画面にせず、展開したRepositoryの直下へファイルツリー形式で表示する。

| キー | 操作 |
| --- | --- |
| `j` / `k`、`↓` / `↑` | Issueを選択する |
| `Enter` | Issue詳細と保存済みのユーザー追加指示からAI向けプロンプトを生成してClipboardへコピーする |
| `q` | Tasks画面へ戻る |

## Popup

popupは現在の画面の中央に重ねて表示する。
背後の画面は表示したまま操作不能とし、最前面のpopupだけが入力を受け取る。
popup表示時はTask一覧をdimで再描画し、その上へpopupを重ねる。
popupの本文、外枠、区切り線はTerminalの既定前景色・背景色を使用する。見出しは既定色の太字、右側と下側のブロック文字の影は既定色のdim表示とする。
popupはTerminalの上下左右を12セルずつ残す大きさで画面中央に表示する。小さいTerminalでは最小panelサイズを維持できるまで余白を自動的に縮める。
枠線には` ┌─┐ `、` │ │ `、` └─┘ `の連続したUnicode罫線を使用する。
Task操作の成功時はpopupを表示せず、すべての保存失敗時はエラーpopupを表示する。
`Enter`または`q`で結果popupを閉じるまで、背後の一覧操作は受け付けない。

### テキスト入力

- 追加・編集の入力popupではハードウェアカーソルを表示し、IMEが変換候補の基準位置として利用できるようにする。
- カーソルはUTF-8文字のTerminal表示幅と折り返しを考慮して入力末尾へ配置する。
- 入力popupを閉じた後はハードウェアカーソルを再び非表示にする。

```text
┌─ Taskを編集 ────────────────────────────────────┐
│ Taskタイトル                                    │
│ Task操作を実装する█                             │
│                                                │
│ Enter 保存   Esc キャンセル                     │
└────────────────────────────────────────────────┘
```

- 追加時は空の入力欄を表示する。
- 編集時は既存タイトル全体を入力済みにし、カーソルを末尾へ置く。
- `←`、`→`、`Home`、`End`、`Backspace`、`Delete`およびUTF-8文字入力に対応する。
- `Enter`で入力を検証し、変更を適用する。
- 検証エラーはpopup内へ表示し、保存済みデータを変更しない。
- `Esc`で入力を破棄して一覧へ戻る。

### 確認

削除と承認には共通形式の確認popupを使用する。

```text
┌─ Taskを削除しますか？ ──────────────────────────┐
│ 「Task操作を実装する」を削除します。             │
│ この操作は元に戻せません。                       │
│                                                │
│ y 削除   n/Esc キャンセル                       │
└────────────────────────────────────────────────┘
```

- 小文字の`y`だけを確定として扱う。
- `n`、`Esc`、`Enter`およびその他のキーはキャンセルとして扱う。
- 確認をキャンセルした場合、ファイルへの書き込みや選択位置の変更を行わない。

## 確認操作の方針

| 操作 | 確認 | 理由 |
| --- | --- | --- |
| Taskの完了状態を切り替える | なし | 元に戻せる |
| タイトルを追加・編集する | 入力検証のみ | 入力内容が画面に表示される |
| 項目を並べ替える | なし | 再度並べ替えて戻せる |
| Taskを一件削除する | あり | 破壊的操作 |
| ProposalのTask候補を削除する | あり | 破壊的操作 |
| Proposalを承認する | あり | 複数Taskを追加しProposalを削除する |
| 未保存変更なしで終了する | なし | データを失わない |
| 未保存変更ありで終了する | あり | 意図しない変更破棄を防ぐ |

Proposalの承認確認では、追加するTask数とProposalが削除されることを明示する。
Proposalの検証が成功した場合だけ承認操作を有効にする。

## 終了と入力中断

- サイドバーでは`q`で終了する。Tasks詳細での`q`も終了する。
- Proposal画面では`q`でTasks画面へ戻り、TUIは終了しない。
- 編集入力中の`Ctrl-C`は変更を破棄して呼び出し元の画面へ戻る。
- 読み込み、検証、保存のエラーを含むすべての終了経路で、Terminal設定、
  カーソル表示、代替画面を復元する。

Task操作は、成功するたびにAtomic保存し、一覧画面へ戻る。
保存に失敗した場合はメモリ上の変更も元に戻し、エラーpopupを表示する。
Proposal編集は編集中に未保存状態を保持する可能性があるため、終了確認は引き続き必要となる。

## エラーと小さいTerminal

- 入力検証エラーは操作中のpopup内へ表示する。
- 読み込み・保存エラーは操作を止めるエラーpopupで表示し、メモリ上の表示を最後に保存が成功した状態と一致させる。
- Terminalが最小サイズを下回った場合は通常操作を停止し、必要な画面サイズと終了キーだけを表示する。
- リサイズによって必要な画面サイズへ戻った場合、以前の画面、選択位置、スクロール位置、popupを再描画する。

## 状態遷移の概要

```text
サイドバー ←──Tab──→ 詳細画面
    │                    │
    ├─ タスク一覧 ───────┼─ p ─ Proposal一覧
    ├─ リポジトリ一覧    ├─ g ─ Issue一覧
    │       └─ Space ─ Repository直下のIssueを展開
    ├─ プロンプト編集 ─ e ─ 外部エディタ
    └─ ヘルプ            └─ d/A ─ 確認
```

popupをキャンセルした場合は、データを変更せず、必ず呼び出し元の一覧へ戻る。
