# TUI操作設計

この文書では、`ztodo tui`の画面構成と操作規則を定義する。
実装はキーボード操作を中心とし、既存のANSI Terminalバックエンドを使用する。

## 基本方針

- 現在の操作対象と利用可能なキーを常に画面へ表示する。
- `Esc`は現在のpopupや編集をキャンセルし、一つ前の状態へ戻る。
- 破壊的操作はキャンセルを既定とし、小文字の`y`が入力された場合だけ実行する。
- Taskの完了状態は元に戻せるため、変更時に確認を求めない。
- 項目を並べ替えた後も、移動した項目を選択し続ける。
- 項目を削除した後は次の項目を選択する。末尾を削除した場合は一つ前を選択する。
- 入力内容の検証が成功するまでファイルを変更しない。

## 画面構成

画面上部のタブで、二つの最上位画面を切り替える。

```text
 ztodo   [Tasks]  Proposal
────────────────────────────────────────────────────────────
 > [ ]    3  Task一覧とProposalの画面を設計する
   [x]    5  読み取り専用のTask一覧を実装する
   [ ]    6  Task操作を実装する

────────────────────────────────────────────────────────────
 ↑/k ↓/j 選択  a 追加  e 編集  Space 完了切替  d 削除
 K/J 並び替え  Tab Proposal  ? ヘルプ        q 終了
```

### Tasks画面

- メイン領域へ、保存されている順序で全Taskを表示する。
- 各行には完了状態、変更されないTask ID、タイトルを表示する。
- 選択中の行をハイライトする。
- 項目数が多い場合は、選択行が表示範囲内に残るようスクロールする。
- Taskがない場合は`Taskはありません。aで追加できます。`と表示する。

### Proposal画面

```text
 ztodo    Tasks  [Proposal]
────────────────────────────────────────────────────────────
 GitHub owner/repo #24: Issueのタイトル
 概要: Proposalの概要

 > 1. 最初のTask候補
   2. 次のTask候補

────────────────────────────────────────────────────────────
 ↑/k ↓/j 選択  a 追加  e 編集  d 削除  K/J 並び替え
 A 承認           Tab Tasks    ? ヘルプ  q 終了
```

- ヘッダーへProposalの生成元と概要を表示する。
- メイン領域へProposal内の順序でTask候補を表示する。
- Proposalがない場合は、`ztodo issue`と`ztodo import`による作成方法を表示する。
- 最初のTUI実装ではProposalのメタデータを読み取り専用とする。
- Task候補の編集にはTask編集と共通の入力popupを使用する。

## フォーカスと移動

フォーカスの優先順位を次のように定める。

1. 入力または確認popup
2. 現在の画面で選択されている行
3. 選択されている最上位タブ

popupが開いていない場合だけ、`Tab`と`Shift-Tab`でTasksとProposalを切り替える。
各画面は、それぞれの選択行とスクロール位置を保持する。
タブの切り替えによってデータを変更してはならない。

一覧内では次のキーを使用する。

- `↑`または`k`：一つ前の行を選択する
- `↓`または`j`：一つ次の行を選択する
- `Home`または`g`：先頭行を選択する
- `End`または`G`：末尾行を選択する
- `PageUp`または`PageDown`：表示一画面分移動する
- `K`または`J`：選択中の項目を一つ上または下へ移動する

一覧の端から反対側へ循環移動はせず、先頭または末尾で停止する。

## キーバインド

### 共通操作

| キー | 操作 |
| --- | --- |
| `Tab` / `Shift-Tab` | TasksとProposalを切り替える |
| `?` | 現在の画面に対応したヘルプpopupを開く |
| `q` | 終了する。未保存の変更がある場合は終了確認を開く |
| `Esc` | 最前面のpopupを閉じる、または編集をキャンセルする |
| `Ctrl-C` | 現在のpopupをキャンセルする。メイン画面では終了する |

### Tasks画面

| キー | 操作 |
| --- | --- |
| `a` | 空のタイトル入力を開き、Taskを追加する |
| `e` | 選択中のTaskを、現在のタイトルが入力済みの状態で編集する |
| `Space` | 選択中のTaskの未完了と完了を切り替える |
| `d` | 確認後、選択中のTaskを削除する |
| `K` / `J` | 選択中のTaskを一つ上または下へ移動する |

### Proposal画面

| キー | 操作 |
| --- | --- |
| `a` | Task候補を追加する |
| `e` | 選択中のTask候補を、現在のタイトルが入力済みの状態で編集する |
| `d` | 確認後、選択中のTask候補を削除する |
| `K` / `J` | 選択中のTask候補を一つ上または下へ移動する |
| `A` | Proposalを検証し、全体の承認確認を開く |

項目の選択が必要なキーは、一覧が空の場合には何もしない。
画面下部には、その時点で実行可能な操作だけを表示する。

## Popup

popupは現在の画面の中央に重ねて表示する。
背後の画面は表示したまま操作不能とし、最前面のpopupだけが入力を受け取る。

### テキスト入力

```text
┌─ Taskを編集 ────────────────────────────────────┐
│ Taskタイトル                                    │
│ Task操作を実装する█                             │
│                                                │
│ Enter 保存   Esc キャンセル                     │
└────────────────────────────────────────────────┘
```

- 追加時は空の入力欄を表示する。
- 編集時は既存タイトル全体を入力済みにし、カーソルを末尾へ置く。
- `←`、`→`、`Home`、`End`、`Backspace`、`Delete`およびUTF-8文字入力に対応する。
- `Enter`で入力を検証し、変更を適用する。
- 検証エラーはpopup内へ表示し、保存済みデータを変更しない。
- `Esc`で入力を破棄して一覧へ戻る。

### 確認

削除と承認には共通形式の確認popupを使用する。

```text
┌─ Taskを削除しますか？ ──────────────────────────┐
│ 「Task操作を実装する」を削除します。             │
│ この操作は元に戻せません。                       │
│                                                │
│ y 削除   n/Esc キャンセル                       │
└────────────────────────────────────────────────┘
```

- 小文字の`y`だけを確定として扱う。
- `n`、`Esc`、`Enter`およびその他のキーはキャンセルとして扱う。
- 確認をキャンセルした場合、ファイルへの書き込みや選択位置の変更を行わない。

## 確認操作の方針

| 操作 | 確認 | 理由 |
| --- | --- | --- |
| Taskの完了状態を切り替える | なし | 元に戻せる |
| タイトルを追加・編集する | 入力検証のみ | 入力内容が画面に表示される |
| 項目を並べ替える | なし | 再度並べ替えて戻せる |
| Taskを一件削除する | あり | 破壊的操作 |
| ProposalのTask候補を削除する | あり | 破壊的操作 |
| Proposalを承認する | あり | 複数Taskを追加しProposalを削除する |
| 未保存変更なしで終了する | なし | データを失わない |
| 未保存変更ありで終了する | あり | 意図しない変更破棄を防ぐ |

Proposalの承認確認では、追加するTask数とProposalが削除されることを明示する。
Proposalの検証が成功した場合だけ承認操作を有効にする。

## 終了と入力中断

- 未保存の変更がなければ、`q`で直ちに終了する。
- 未保存の変更がある場合、`q`で`変更を保存して終了しますか？`を表示する。
  - `y`：保存して終了する
  - `n`：変更を破棄して終了する
  - `Esc`：終了せず元の画面へ戻る
- メイン画面でのEOFまたは`Ctrl-C`も、未保存状態に応じて同じ終了規則を適用する。
- 読み込み、検証、保存のエラーを含むすべての終了経路で、Terminal設定、
  カーソル表示、代替画面を復元する。

Task操作は、成功するたびにAtomic保存する実装を優先する。
Proposal編集は編集中に未保存状態を保持する可能性があるため、終了確認は引き続き必要となる。

## エラーと小さいTerminal

- 入力検証エラーは操作中のpopup内へ表示する。
- 読み込み・保存エラーは操作を止めるエラーpopupで表示し、メモリ上の表示を最後に保存が成功した状態と一致させる。
- Terminalが最小サイズを下回った場合は通常操作を停止し、必要な画面サイズと終了キーだけを表示する。
- リサイズによって必要な画面サイズへ戻った場合、以前の画面、選択位置、スクロール位置、popupを再描画する。

## 状態遷移の概要

```text
Tasks一覧 ──Tab── Proposal一覧
    │                  │
    ├─ a/e ─ 入力 ─────┤
    ├─ d ─ 削除確認 ───┤
    │                  └─ A ─ 承認確認
    ├─ ? ─ ヘルプ
    └─ q ─ 終了確認（未保存時のみ）── 終了
```

popupをキャンセルした場合は、データを変更せず、必ず呼び出し元の一覧へ戻る。
